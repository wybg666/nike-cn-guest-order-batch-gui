# Nike 访客订单批量查询 GUI（非官方）

基于 Python、Tkinter、Requests 和 OpenPyXL 的桌面工具，用于批量查询你本人或已获得授权的 Nike 中国访客订单，并将订单摘要、商品明细和失败记录整理为 Excel 文件。

本项目不隶属于 Nike，也不是 Nike 官方工具。程序依赖第三方接口，接口行为、访问要求和返回格式可能变化；**不保证当前能够成功查询所有订单**。

> **使用前请了解**
>
> - 需要自行提供有效且有权使用的订单号、对应手机号及代理。本发布版不附带真实订单、手机号或代理凭据。
> - 当前 GUI **必须填写代理列表**，没有直连模式。
> - 默认查询流程使用 GET；可选的“补充支付单”会发送 POST，不能把整个程序视为始终只读。
> - 本地设置、运行日志和导出文件可能包含个人信息及代理认证凭据，不要上传到公开仓库。

## 功能

- 粘贴多行“订单号 + 手机号”，批量查询订单。
- 使用代理池和线程池处理任务，代理列表去重；实际并发数不超过订单数及可用代理数。
- 查询失败后在可用代理范围内再次尝试，记录失败原因和尝试次数。
- 显示进度、成功数、失败数及运行日志。
- 自动导出、手动导出 Excel，包含 `orders`、`items`、`failed` 三张工作表。
- 支持请求停止；已开始的请求需要等待结束，已完成的数据仍可导出。
- 可选补充支付表单信息，默认关闭，详见后文。

## 运行环境

推荐使用 **Windows + Python 3.11**，并确保 Python 安装包含 Tcl/Tk（`tkinter`）。

源码使用 `set[str]` 等语法，语法层面至少需要 Python 3.9；但本发布版固定的 Requests 版本要求 **Python 3.10+**，因此请使用 Python 3.10 或以上，优先选择已用于本地验证的 Python 3.11。其他 Python 版本、依赖组合或操作系统未验证。启动及打包脚本面向 Windows。

第三方运行依赖在 `requirements.txt` 中列出：

- `requests==2.34.2`
- `openpyxl==3.1.5`

上述版本用于本地离线验证，不是包含全部间接依赖的完整锁文件。`tkinter` 由 Python 安装提供，不能通过安装以上两个包替代。构建 Windows 程序另外需要 PyInstaller。

## 安装与启动

下载项目或克隆仓库后，在**项目目录**中打开 PowerShell。下面的命令不需要激活虚拟环境，也不需要更改 PowerShell 执行策略。

### 1. 创建虚拟环境并安装依赖

```powershell
py -3.11 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
```

如果系统没有 `py` 命令，但 `python --version` 显示的是所需版本，可将第一条替换为：

```powershell
python -m venv .venv
```

安装依赖需要连接软件包源。不要从不可信来源安装依赖。

### 2. 启动 GUI

```powershell
.\.venv\Scripts\python.exe nike_guest_batch_gui.py
```

这个方式保留终端，便于看到启动错误。也可以使用无控制台启动器：

```powershell
.\.venv\Scripts\pythonw.exe nike_guest_batch_gui_launcher.pyw
```

项目还提供 `launch_guest_batch_gui.bat` 和 `启动订单查询GUI.bat`。这两个脚本使用 PATH 中的 `python` / `pythonw`，不会自动选择本项目的 `.venv`；缺少依赖时会尝试安装 `requests` 和 `openpyxl`，也不会按 `requirements.txt` 锁定版本。因此优先使用上面的显式虚拟环境命令。

若提示缺少 `tkinter`，请修复或重新安装带 Tcl/Tk 支持的 Python。

## 使用方法

### 1. 填入订单

左侧输入框每行一条，第一列为订单号，第二列为对应手机号。支持 **Tab、空格或英文逗号** 分隔，可以从表格复制两列后粘贴。

以下全部是格式占位符，不是真实订单或手机号，**不能直接用于查询**：

```text
TOKEN_ORDER TOKEN_PHONE
TOKEN_ORDER_2,TOKEN_PHONE_2
```

空行和不足两列的行会被忽略；多于两列时只读取前两列。程序不会验证订单号和手机号的格式，也不会自动去重订单。请在运行前自行检查输入。

### 2. 填入代理

右侧输入框每行一个，支持以下两种格式：

```text
HOST:PORT
HOST:PORT:TOKEN_USER:TOKEN_PASSWORD
```

`HOST`、`PORT`、`TOKEN_USER`、`TOKEN_PASSWORD` 均为占位符，需要替换为你有权使用的代理地址、端口、用户名和密码。内部按 HTTP 代理构造连接；不支持直接填入带协议前缀的完整代理 URL，也没有专门处理 IPv6、包含冒号的认证信息或 SOCKS 代理。

请不要在 Issue、README、截图或示例配置中公开代理凭据。

### 3. 检查参数

| 参数 | 默认值 | 说明 |
| --- | --- | --- |
| `Threads` | 5 | 期望的工作线程数；实际并发还受订单数和代理数限制。 |
| `Retries` | 3 | 实际表示每个订单的**总尝试次数上限**，包含第一次请求，并非首次请求之后再重试 3 次；最多为配置值和代理池大小中的较小值。 |
| `Precheck proxies` | 开启 | 对代理进行接口连通性预检，不保证正式查询成功。 |
| `补充支付单(POST+Jobs)` | 关闭 | 会触发额外支付表单请求，见下文。 |

**代理预检不是本地检查，也不是单纯检测端口。** 它会取输入中的第一组订单号和手机号，通过每个代理向订单接口发送真实 GET 请求。预检的并发上限单独设为 20，不受 `Threads` 值控制；它会增加请求量。

预检把部分非成功 HTTP 状态（包括 400、401、403、404、429）也视为连接可达。因此“预检通过”不等于代理可以成功查单，更不等于订单存在。

程序没有内建的全局请求速率限制，也没有针对 HTTP 429 的退避等待机制。不要把调低线程数当作精确限速；遇到限流或访问拒绝时应停止任务，检查服务方访问要求，而不是持续提高并发或尝试次数。

### 4. 运行、停止与导出

确认数据及参数后，点击 **运行批量查单**。处理完成后会自动导出 Excel，也可以使用 **导出到桌面（xlsx）**。

点击 **停止** 会发出停止请求，但不会强制取消正在进行的网络请求。程序会等待这些请求结束，整理已完成的数据；未处理的记录不会被伪装成成功结果。本工具不支持断点续跑或持久化任务队列。

## 可选的支付表单功能

默认不勾选 **补充支付单(POST+Jobs)**。

开启后，程序会在订单查询成功后，尝试使用返回的支付审批信息：

1. 向 deferred payment form 接口发送 **POST** 请求。
2. 对返回的任务发送 GET 请求，最多轮询 8 次。
3. 提取支付表单状态、任务 ID、有效期、表单 action 和二维码链接等信息。

**这一步可能创建或刷新服务端支付表单任务，有服务端副作用，不是纯读取操作。** 只在明确需要、理解其影响且对相关订单有权限时启用。代码不自动提交最终付款表单，也不代表已经完成扣款或支付；不要把它介绍为自动支付工具。

支付表单补充失败时，普通订单查询仍可能被统计为成功。请另外查看 Excel 中的 `deferredFormError` 等字段；界面的“成功”数量不保证所有补充字段都有结果。

## 导出结果与敏感信息

文件名形式为 `nike_guest_orders_YYYYMMDD-HHMMSS.xlsx`。程序优先寻找用户的 `Desktop` 或 `OneDrive/Desktop` 目录，均不存在时保存到用户主目录。

| 工作表 | 内容 |
| --- | --- |
| `orders` | 订单状态、金额、付款状态、收件信息、可选支付表单字段及原始 JSON 等。 |
| `items` | 商品信息、尺码、数量、商品状态、预计配送时间等接口返回内容。 |
| `failed` | 订单号、查询手机号、错误信息、所用代理及尝试次数。 |

字段是否有值取决于接口返回内容。本工具不保证所有字段、所有订单类型都完整适配。

**导出表格可能包含姓名、电话号码、收货地址、订单数据、支付相关链接和完整原始响应。失败表和界面日志还可能包含带用户名、密码的原始代理字符串。** 请保存在受控位置；分享前脱敏，不要作为仓库示例文件上传。

## 本地设置

程序在脚本所在目录（打包后为 EXE 所在目录）读写 `nike_guest_batch_gui_settings.json`，保存线程数、尝试次数、预检开关和代理列表。

- GUI 启动、运行及关闭等流程会触发设置保存。
- 设置是本地明文 JSON，代理认证信息不会自动加密。
- 源码发布目录提供不含真实凭据的 `nike_guest_batch_gui_settings.example.json` 供参考；无需复制即可启动，程序会生成运行配置。
- 不要将真实运行配置复制到公开目录、截图、压缩包或 Release。

`.gitignore` 已排除本地运行设置、虚拟环境、缓存和常见输出，但 **`.gitignore` 不是脱敏工具，也不会阻止通过 GitHub 网页手动上传这些文件**；已经被 Git 跟踪的文件也不会因为新增忽略规则自动消失。

## 构建 Windows 程序

推荐在 Windows 的同一虚拟环境中构建：

```powershell
.\.venv\Scripts\python.exe -m pip install pyinstaller
.\.venv\Scripts\python.exe -m PyInstaller --noconfirm --clean --windowed --onedir --name NikeGuestBatchGUI nike_guest_batch_gui_launcher.pyw
```

输出入口为：

```text
dist/NikeGuestBatchGUI/NikeGuestBatchGUI.exe
```

也可以使用 `build_guest_batch_gui.bat`，但它调用 PATH 中的 `python`，请先确认其指向正确环境。

本文仅提供构建步骤，**不声称 EXE 已构建或在其他 Windows 电脑上验证过**。制作 Release 前，请在干净环境自行检查启动、依赖及发布包内容。
